// How to Work: ETL and ELT 

/*
    Data Pipline can be :
       ETL : Data is stable - from x to y directly 
             and transformation happens in one place.
       ELT : Data is not stable - we need transformation .
         --> Ex: Source(API = Application Programming Interface)  - Stagging Area(Here Transformation) -Target
       T(Transformation) : we transforme data means we change data into useful format 

    But How to choose the right data pipline : 
        - Volumetrie(Quantity of data)
        - Conformite (Security for personnal data (like morrocan data should not be in cloud,cloud data platform like AWS , azure , BigQuery, ..))
        - Felexiblite (Ability to change transformations)
        - Coût de calcul (Cost of processing data)
        - Vitesse (How quickly data becomes available)
    
    When to use ELT and ETL:
        - ELT : Get all Data .And then we gonne look what we need from this data , this is good to get backup to the historical data
        - ETL: We do not need all data for get Insights

*/

// Data Lake , Lakehouse , Data Warehouses


/*
   - Data Lake (Cloud Storage ) : centralized storage that can hold anything (vides , files , parquet,...)
     --> We use this beacause we do not know why we need this data 

    - Data Warehouse(Big Query[Anayltics exit here]): 
       --> There is restriction , wich mean:
         * data is structured (csv file). and data come from diffrent source. we know where we want to go. 
         * data warehouse is result of data modeling. we start by data modeling and then data warehouse.

    - Lakehouse: We merge Datalake and Data Warehouse. Means I am dealing with data as files but storage as Lake (there is parquet file).

    - Delta Lake: Makes a Lakehouse powerful by storing data in Parquet files while allowing us to manage and query data as tables using SQL.

    - Lakehouse Support : 
       -Transactin ACID
       - Time Travel
       -Enforce Schema : we can not insert something diffrent to table model 
       -Upsert (merge) : insert and update in same time.

*/

// OLAP  vs OLTP 

/*
   - We need to know our goal : analyzing data or performing transactions . 
   - These are two concepts that help us define how we use a database.

   OLTP(Transactional):

      In this case . Our goal is to store and manage data for daily operations (CRUD(CREATE,READ,UPDATE,DELETE) Operations)
      - Example : recording a bank transaction
      - Example : Oracle , MySQL , PostgreSQL ,...
    
   OLAP(Analytical)  :
     in this case . Our  goal is to analyze data , often including historical data , to understand trends and make decisions .
        -Example : analyzing bank transactions over the last 5 years 

/*
